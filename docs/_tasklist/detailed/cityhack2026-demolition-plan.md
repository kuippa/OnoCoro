## 不燃ゴミ（GarbageCubeNoBurn）2026-08-29 追加

解体廃棄物を可燃・不燃に分けて数えるために追加した。
実務では処理先も処理費用も異なり、仮置場の計画に効いてくるため。

### プレファブ要件

**配置場所**: `Assets/Resources/Prefabs/WorkUnit/GarbageCubeNoBurn.prefab`

`GarbageCube.prefab` を複製してマテリアルを差し替えるのが早い。
コンクリートがら・金属を想定しているので `DebrisConcrete` か
`DebrisMetal` のテクスチャが合う。

| 項目 | 内容 |
|------|------|
| タグ | `GarbageNoBurn`（TagManager に追加済み。Factory 側でも設定する） |
| スケール | `1, 1, 1`（サイズは生成時にインスタンスへ設定するため） |
| Collider / Rigidbody | 無ければ Factory が付ける |

[NOTE] プレファブが未作成の間は、可燃ゴミのプレファブで代用して動く。
見た目だけ可燃と同じになり、タグと集計は不燃として扱われる。

### 割合の設定

ステージ YAML の `demolition` セクションに `noncombustible_ratio`（0.0〜1.0）を追加。

```yaml
demolition:
  - type: wood
    noncombustible_ratio: 0.4   # 木くず中心なので可燃寄り
  - type: concrete
    noncombustible_ratio: 0.9   # コンクリートがら中心でほぼ不燃
```

[WARN] 現在の値は**構造ごとの傾向だけを反映した仮の値**。
PLATEAU 技術資料 `plateau_tech_doc_0015` の P43 以降にある組成比で差し替えること。
（資料 URL: https://www.mlit.go.jp/plateau/file/libraries/doc/plateau_tech_doc_0015_ver01.pdf）

### なぜタグを分けるか

延焼処理（`Flame` / `Burning`）は tag `Garbage` を対象にしている。
タグを分けることで**不燃ゴミは自動的に延焼対象から外れる**。
コンクリートがらが燃えないのは物理的にも正しい。

## コンセプト

**「巨大な猫が街を壊すと、建物の構造・規模に応じた廃材が散らばり、4t トラック何杯分かが分かる。跡地には花が咲く」**

災害・解体時に発生する廃棄物量を、実在の街（PLATEAU）で体感的に可視化する。
潮位・内水氾濫がテーマとして混み合う中、**災害廃棄物**という別角度で差別化する。

## 設計判断（2026-08-28 決定）

| 論点 | 決定 | 理由 |
|------|------|------|
| 瓦礫量の算定基準 | **延床面積 × 構造別の発生原単位**（用途地域からの推定ではない） | 用途地域は土地の規制情報で間接的。実務（災害廃棄物対策指針）は延床面積あたりの原単位を使う。`bldg:totalarea` が既に計算済みで即使える |
| 構造種別の取得 | PLATEAU 属性から**直接取得を試みる**（推定はフォールバック） | `uro:buildingStructureType` / `uro:fireproofStructureType` が入っていれば推定不要。入っていなければ `bldg:usage`（取得済み）で代用 |
| 猫の実装 | **敵ユニットとして実装**（PlayerArmature の差し替えはしない） | Humanoid リグ・Animator の互換性リスクを回避。既存の NavMeshAgent 経路移動（EnemyLitter / spawn_enemy_unit）に乗れる。モデルは静的でよく精度も不要 |
| 対象マップ | **既存マップ（三鷹井の頭５丁目）で機能実装**。舞鶴は後日差し替え | 残り 7 日。GIS 新規取得は後回しにして機能を優先 |
| 建物破壊の挙動 | マテリアル変更ではなく**完全消去＝更地化**してから瓦礫放出 | 「壊した」ことが視覚的に明快。`PlateauBuildingInteractor.DeleteBuilding()` が既存 |

## 既存資産の棚卸し（そのまま使えるもの）

| 既存 | 用途 |
|------|------|
| `PlateauDataExtractor`：`bldg:usage`（用途・コードリスト対応）/ `measuredheight` / `floor`（底面積）/ `floors` / **`totalarea`（延床面積）** | 瓦礫量算定の入力がすべて揃っている |
| `PlateauBuildingInteractor.DeleteBuilding()` | 更地化 |
| `PlateauCubeMaker.BreakUpBuildingCube()` | 建物周囲への瓦礫の円形散布 |
| `GarbageCubeSpawner.SpawnGarbageCubeAsync()` | 大量瓦礫のフレーム分散生成 |
| `GarbageCubeFactory`（small/normal/big） | 瓦礫の粒度分け |
| NavMeshAgent 経路移動（`AINavigationManager` / `EnemyLitter` / `spawn_enemy_unit` / `pathmakers`） | 猫の経路移動 |
| YAML 外部化の仕組み（`infrastructures.yaml` 方式） | 係数表を再コンパイルなしで差し替え |
| `InvestmentLedger` の積算パターン | 瓦礫量の積算に流用 |

**新規実装は思ったより少ない。**組み替えが主。

## リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| 構造種別属性がデータに無い | T3 の根拠が弱くなる | `bldg:usage`（取得済み）＋階数から推定にフォールバック。T0 で早期判明させる |
| パートナーの回答が遅い | T3 が止まる | 係数は YAML 外部化し、**仮の値で先に実装**。後から差し替えるだけにする |
| 猫モデルが期待通り動かない | T4 が溶ける | 敵ユニット化により依存を分離済み。最悪キューブでも成立する |
| 瓦礫の大量生成で処理落ち | 動画が撮れない | 既存の `SpawnGarbageCubeAsync`（フレーム分散）を使用。上限値を設ける |
