## 設計判断の記録（2026-06-12 ヒアリング結果）

| 論点 | 決定 | 理由 |
|------|------|------|
| 火災の視認性問題 | 小マップを新設（建物数の少ない PLATEAU シーン） | 体験設計の本命。「短時間で配置→消火を体験できる建物数が少ないマップ」（notes_season3.md 案 1） |
| 施策の効果モデル | 統計効果型（効果範囲内の被害率を下げる） | WaterTurret のリアルタイム撃退では延焼を止められない。「どこに投資したか」が結果を決める方が防災教育ツールとして筋が良く、W3 の ROI 計算と直結 |
| 床抜け（BUG-S3-002） | カメラシェイク化を W2 で実施 | DEM を動かさずカメラを揺らす方式へ変更し根本解消。オブジェクト・プレイヤーの奈落落下が無くなる |
| ヒートマップ | 簡易版（次年の倒壊予定/出火エリアの色付け） | 既存の doom マテリアル変更機構を流用して軽く実装。「どこが危ないか見てから投資する」体験を成立させる |

## 実装タスク

### Task 1: カメラシェイク化（エージェント・1-1.5h）

地震の表現を「DEM・建物のテレポート変位」から「カメラの揺れ」に変更する。

- [ ] Earthquake.cs を改修: DEM/建物の transform 変位を廃止し、メインカメラ
  （Cinemachine 構成を確認の上）に減衰付き Sin 振動を適用
- [ ] 既存の振幅計算（CalcSin / CalcAmpDecay）は流用
- [ ] quake_fire パターンのタイミング制約コメントを更新
  （揺れ中スポーン禁止の制約が消えるが、演出順序として倒壊→出火は揺れ後を維持）
- [ ] 武蔵野堺南木密で床抜けが起きないことを確認（BUG-S3-002 クローズ）

**リスク**: Cinemachine の Virtual Camera 構成によっては素direct transform 操作が
効かない場合がある（Cinemachine Impulse の利用を検討）。着手時にカメラ構成を先に調査する。

### Task 2: 小マップ新設（ユーザー Editor 作業 1-1.5h + エージェント 0.5h）

**ユーザー作業**（手順書はエージェントが Task 2 着手時に作成）:

- [ ] 武蔵野堺南木密シーンを複製し `SimQuarter`（仮名・要相談）として保存
- [ ] 町内会エリア相当（目安: 建物 30-80 棟）を残して範囲外の建物・DEM タイルを削除
  ※ 既存 PLATEAU データの間引きが最速。新規インポートは行わない
- [ ] ビルドのシーンリストに追加

**エージェント作業**:

- [ ] `SimQuarter.yaml` 作成（years 3 年構成、quake_fire パターン流用、小マップ用に調整）
- [ ] stagelist.csv への登録（Shift-JIS エンコーディング注意）
- [ ] プレイヤー初期位置・カメラからエリア全体が見渡せることの確認項目作成

**判断メモ**: シーン削減で建物リストが小さくなるため、building_break の
「先頭 N 棟を決定的に選ぶ」挙動でも年ごとの倒壊が視界内に収まる。
BuildingBreak のランダム化は必須ではなくなった（必要なら W3 で）。

### Task 3: 統計効果型施策の実装（エージェント・2h）

施策 3 種を「効果範囲を持つ配置物」として実装する。

**データ定義**（YAML またはコード定数。W2 はコード定数で開始）:

| 施策 | コスト | 効果 | 範囲（目安） |
|------|--------|------|------|
| 消火栓 Hydrant | 50 | 範囲内の FireCube を周期的に鎮火（消火力 高） | 小 |
| 防火水槽 Cistern | 30 | 範囲内の延焼（FireCube 増殖）を抑制 | 中 |
| 避難広場 Plaza | 100 | 範囲内の人的被害補正（W3 の結果計算で使用。W2 では記録のみ） | 大 |

**実装内容**:

- [ ] `GameEnum.ModelsType` に Hydrant / Cistern / Plaza を追加
- [ ] `InfrastructureUnit`（Game/Units/Structures/）: 効果範囲・施策タイプを持つ配置物。
  既存 Tower 系の配置フロー（TAB ビルドメニュー + ItemHolder）に乗せる
- [ ] `InfrastructureSystem`（Game/Systems/Simulation/）: 周期チェックで
  範囲内の FireCube に鎮火処理 / 延焼抑制フラグを適用
- [ ] 効果範囲の可視化（半透明円。配置時 + 配置後常時表示の切り替えは後日調整）
- [ ] `InvestmentLedger`（Game/Systems/Simulation/）: 年ごとの投資額を記録（W3 の ROI 計算の土台）
- [ ] SpawnController に 3 種の生成分岐を追加、Prefab は既存ユニットの流用形状で仮作成

**スコープ外（W3 以降）**: 被害率の正式計算式、Plaza の人的被害モデル、施策の撤去/移設

### Task 4: 施策選択 UI（エージェント・0.5-1h）

- [ ] 既存の TAB ビルドメニュー（ユニット作成メニュー）に施策 3 種を追加する方式を第一候補に調査
  - itemlists に追加すれば既存フローに乗る見込み。乗らない場合のみ専用ボタンを YearPanel に追加
- [ ] 配置は既存のアイテムストック → マーカークリック方式を流用
- [ ] Placement フェーズ中のみ配置可能とする制御（YearRunning 中は配置不可）

### Task 5: 簡易ヒートマップ（エージェント・0.5-1h）

- [ ] Placement フェーズ中、次年の `years` 定義から倒壊・出火予定エリアを推定し、
  対象建物を警告色マテリアルで強調（既存 doom マテリアル機構を流用）

- [ ] 「色付けの根拠（次年イベントの事前読み）」はネタバレ設計であることを計画上明記
  ※ ワークショップでは「ハザードマップを見て投資する」体験として意図どおり

### Task 6: PlayMode 検証（ユーザー + エージェント・30 分）

- [ ] 小マップで Year 1-3 完走、火災・倒壊が視界内で起きる

## タスク順序と分担

```
Task 1 カメラシェイク（エージェント）→ ユーザー検証
Task 2 小マップ（ユーザー Editor 作業と並行で エージェントが YAML 準備）
Task 3 施策実装（エージェント）→ Task 4 UI（エージェント）
Task 5 ヒートマップ（エージェント）
Task 6 検証（ユーザー目視 + エージェントログ解析）
```

Task 1 と Task 2 は独立しているため、ユーザーの Editor 作業時間が取れない週前半は
Task 1 → 3 → 4 を先行できる。

## リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| Cinemachine 構成でカメラ直接操作が効かない | Task 1 手戻り | 着手時にカメラ構成を調査してから方式決定（Impulse 候補） |
| 小マップの建物削除で PLATEAU 参照が壊れる | シーンエラー | 複製シーンで作業し原本は触らない。削除は建物 GameObject 単位に留める |
| 施策の TAB メニュー統合が既存フローに乗らない | Task 4 工数増 | 乗らない場合は YearPanel に専用ボタン 3 つ（W1 と同じ自己構築方式） |
| 統計効果のバランス（強すぎ/弱すぎ） | 体験の説得力低下 | W2 では効果を定数化して調整可能にしておき、バランス調整は W3 のデモ準備で実施 |
| 工数超過（合計 5h 超） | W3 圧迫 | 優先順位: Task 3 > 2 > 1 > 4 > 5。ヒートマップは最悪 W3 送り |
