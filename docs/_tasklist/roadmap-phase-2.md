### 2.1: Stage 1 バグ修正サイクル（3-5人日）

**目標**: Stage 1 テスト中に発見された進行不能バグを修正・ドキュメント化  
**優先度**: 最高  
**実施タイミング**: Phase 2.0 完了後、進行不能バグ発見時に即座に実施

#### バグ修正の流れ

| ステップ | 内容 | 成果物 |
|---------|------|--------|
| **発見** | Stage 1 テストプレイ中に進行不能バグ発見 | バグの概要記録 |
| **分析** | バグの原因・再現手順を特定 | 原因分析ドキュメント |
| **修正** | コード修正・テスト | 修正コミット |
| **ドキュメント化** | unity-design-patterns.md などに追記 | 知識ベース更新 |

#### 対象バグ例

現在までに確認されたバグ：
- OnTriggerEnter/Exit の複数発火による状態不一致 [修正済み]
- Physics.Raycast がトリガーコライダーに引っかかる [修正済み]

#### チェックリスト

- [x] 進行不能バグ 完全解決
- [x] 修正内容を unity-design-patterns.md に記録
- [x] 修正後の Stage 1 クリア可能確認
- [x] ログに新しい Error/Exception なし

**期間**: 3-5日  
**進捗**: ✅ 完了（2026-02-11 - StageGoal/UINotice/static flag fixes）

### 2.2: Stage 1 品質向上（7-10人日）

**目標**: Stage 1 の UI・バグ・パフォーマンスを改善し、外部フィードバック収集に向けた品質レベルに引き上げる  
**優先度**: 最高  
**進捗**: 進行中（40% - UI A1・A2・B1 完了）  
**注記**: カメラ潜り込み問題（A3）は重処理のため Phase 3 以降に延期

#### 発見された問題点

**[A] UI 改善** - 優先度：最高
- ✅ CreateWindow の作成時間インディケーターバーが初期化されていない → **完了**
- ✅ Tooltip でアイテム説明を表示しているが、事前に説明欄を設ける必要（最初から表示） → **完了**
- ❌ カメラが地面の下に潜る問題がある → **Phase 3 以降に延期**（重処理）

**[B] バグ修正** - 優先度：高
- ✅ ゴム増加時に失敗判定になるべきだがクリア判定になる → **完了**

**[C] パフォーマンス改善** - 優先度：高
- 低スペックマシンで初期画面表示まで 30 秒かかる
- スプライト表示は不要（削除可能）

| **C** | パフォーマンス改善 | 起動時間短縮・スプライト削除 | 3-4日 | 🔄 進行中 |

### 2.3: 外部フィードバック収集（3-5人日）

**目標**: Stage 1 ビルドを外部テスターに配布し、ユーザーフィードバックを収集  
**優先度**: 最高  
**実施タイミング**: Phase 2.2 完了後

#### フィードバック収集の流れ

| ステップ | 内容 | 成果物 |
|---------|------|--------|
| **配布** | 複数テスター（5 人以上）に Build を配布 | フィードバック募集メール |
| **テスト** | テスターが環境でテスト実施 | テストログ・スクリーンショット |
| **収集** | フィードバック・問題報告を収集 | フィードバック実績表 |
| **分析** | 頻度・重要度で分類・優先度付け | 優先度付きバグリスト |

#### 収集対象

| 項目 | 確認内容 | 優先度 |
|------|---------|--------|
| **進行可能性** | ゲーム開始～クリアまで可能か | 最高 |
| **UI/UX** | ボタン反応、表示の分かりやすさ | 最高 |
| **ゲームバランス** | 難易度は適切か（Easy/Normal） | 高 |
| **パフォーマンス** | FPS、ロード時間、メモリ | 高 |
| **プレイ感** | キャラクター操作性、快適度 | 中 |

- [ ] フィードバック内容をドキュメント化
- [ ] 優先度付け完了
- [ ] 次フェーズ（2.4）での対応方針決定
