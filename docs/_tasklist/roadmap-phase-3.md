## 実装内容詳細

### 3.1: 本格的な QA テスト（12-15人日）

**目標**: Phase 2 で完成した全ステージの包括的テスト・バグ排除  
**優先度**: 最高  
**実施タイミング**: Phase 2（ステージ実装・バグ修正）完了後

### 相違点：Phase 2 と Phase 3 の QA 戦略の区別

| 段階 | フェーズ | テスト対象 | テスト方法 | 優先度 |
|------|---------|----------|----------|--------|
| **開発中** | Phase 2.0-2.2 | 個別ステージ | 開発者テスト（進行可能性） | 最高 |
| **本格QA** | Phase 3.1 | 全ステージ連続 | 複数人・複数周回テスト | 最高 |

#### テスト項目

| バグカテゴリ | テスト内容 | 優先度 |
|-------------|----------|--------|
| **クリア不可** | 敵が詰まる、タワー配置不可、ゴール到達不可 | 最高 |
| **UI 非応答** | ボタン無反応、メニュー固定 | 最高 |
| **データ破損** | ステージロード失敗、YAML パース失敗 | 最高 |
| **クラッシュ** | NullReferenceException、OutOfMemory | 最高 |
| **セーブ・ロード** | ゲーム進行保存失敗 | 高 |

#### テスト実行方法

**複数人による複数周回テスト**（クローズドベータテスト形式）:

```
1. テスターを 2-3 名配置
2. 各テスターが全ステージを独立してプレイ（複数周回）
3. 異なるプレイスタイル（急速クリア、丁寧なクリア等）でバリエーション
4. Development Build で実行、ログ収集
5. 各ステージで以下を記録：
   - クリア可能性（Yes/No）
   - クリア時間（分）
   - バグ発生の有無・内容
   - パフォーマンス（FPS 測定）
6. バグ報告・修正・再テスト
```

#### チェックリスト

- [ ] 複数テスター（2-3名）による複数周回テスト実施
- [ ] 全ステージクリア可能（全テスター確認）
- [ ] クリティカルバグ：0件（進行不能バグなし）
- [ ] 10時間以上連続プレイでクラッシュなし
- [ ] エラーログ出力なし
- [ ] 例外処理が適切に機能
- [ ] 各ステージクリア時間 測定完了

**期間**: 12-15日

### 3.2: パフォーマンス最適化（6-8人日）

**目標**: 60 FPS 安定、メモリ効率化  
**優先度**: 最高

#### 測定項目

| 項目 | 目標値 | 許容範囲 |
|------|--------|---------|
| **フレームレート** | 60 FPS | 最小 45 FPS |
| **メモリ使用量** | < 700 MB | < 1 GB |
| **読み込み時間** | < 5秒 | ステージ切り替え時 |
| **GC 停止時間** | < 16ms | フレーム内 |

#### 最適化対象

- [ ] PLATEAU 地形データ キャッシング
- [ ] TextureMeshPro フォント キャッシング
- [ ] UI アニメーション最適化
- [ ] オブジェクトプーリング導入
- [ ] 不要アセット削除

#### チェックリスト

- [ ] Profiler で全フレーム 60 FPS 以上
- [ ] メモリリーク なし
- [ ] GC.Alloc 最小化

**期間**: 6-8日
