## 🎮 **プロジェクト価値観（Values）**

### 1. 堅牢性（Robustness）

> **Recovery フェーズだからこそ、慎重に**

- 古い参照が残っていてもビルド・実行に支障なし
- Null チェック・防御的プログラミングを徹底
- テストを十分に実施した上でリリース

### 2. 透明性（Transparency）

> **コード・ドキュメント・進捗をすべて公開**

- GitHub を通じた版管理・PR プロセス
- 設計判断を docs/ に記録
- バグ・改善案を _tasklist に可視化

### 3. 知見共有（Knowledge Sharing）

> **同じ悲劇を繰り返さない**

- PLATEAU SDK 活用のベストプラクティスを発信
- Unity × GIS の実装パターンをドキュメント化
- オープンソースコミュニティへの貢献

### 4. 品質重視（Quality First）

> **商業リリースでなくても、高い品質を**

- コード規約（AGENTS.md）を厳格に適用
- テスト・パフォーマンス測定を習慣化
- ユーザー体験を最優先

### 5. 継続性（Sustainability）

> **2 年の空白を繰り返さない**

- Git による分散バックアップ
- ドキュメント充実による後継者への引き継ぎ
- エコシステムの構築

## 🔄 **運用・更新ルール**

### フェーズ完了時の実施項目

フェーズ完了時（2-4 週ごと）に以下を実施：

1. **ステートメント更新** - 完了したマイルストーンを ✅ 記載
2. **成果まとめ** - 達成内容を 1 文で要約
3. **KPI 測定** - 目標値との比較
4. **次フェーズの明確化** - 優先度を確認

### 判断基準

| 判断 | 条件 | 対応 |
|-----|-----|------|
| **フェーズ成功** | マイルストーン 80% 以上達成 | 次フェーズへ進行 |
| **フェーズリスク** | マイルストーン 50-80% | スケジュール延長検討 |
| **フェーズ失敗** | マイルストーン < 50% | 計画見直し・リソース調整 |
